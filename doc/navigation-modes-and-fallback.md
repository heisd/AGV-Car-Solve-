## 1. 概览

本项目设计了**双重导航驱动架构**，可在不同计算资源或仿真阶段下切换。通过配置两套启动脚本，系统既能使用完全物理定位与避障算法的工业级导航栈，也能够回退到不需要建图的轻量级仿真真值驱动方案。

```
                    ┌──────────────────────────────┐
                    │      调度中心 fleet_manager   │
                    └──────────────┬───────────────┘
                                   │ 发布 /goal_pose
                                   ▼
        ┌─────────────────────────────────────────────────────┐
        │                 双重导航驱动选择                     │
        └──────────────┬───────────────────────────────┬──────┘
                       │ (Nav2 模式)                    │ (真值回退模式)
                       ▼                               ▼
            ┌─────────────────────┐         ┌─────────────────────┐
            │   nav2_goal_bridge  │         │  ground_truth_wf    │
            └──────────┬──────────┘         └──────────┬──────────┘
                       │ (NavigateToPose)              │ (直线P控制算法)
                       ▼                               ▼
            ┌─────────────────────┐                    │
            │   Nav2 Navigation   │                    │
            │ (AMCL/Costmap/BT)   │                    │
            └──────────┬──────────┘                    │
                       │ 发布 /cmd_vel                 │ 发布 /cmd_vel

                                       ▼
                            ┌─────────────────────┐
                            │    Gazebo (底盘)    │
                            └─────────────────────┘
```

## 2. Nav2 导航驱动模式

当使用 `warehouse_fleet_nav2.launch.py` 启动系统时，AGV 进入工业级导航模式。

### 2.1 核心组件
* **[nav2_goal_bridge.py](file:///home/li/GazeboLib/src/amr_description/amr_description/nav2_goal_bridge.py)**：作为调度中心与 Nav2 动作接口之间的桥梁。它订阅调度中心发布的 `/{ns}/goal_pose` 话题，并将目标发送给 Nav2 动作服务器。
* **Nav2 Bringup (AMCL + Costmap + BT_Navigator)**：在命名空间内单独运行的一套导航组件。负责激光雷达定位、二维代价地图障碍物规避以及全局/局部路径搜索。

### 2.2 启动与运行逻辑
1. **就绪检测**：在启动时，`nav2_goal_bridge` 会在 `run()` 方法中阻塞并调用 `waitUntilNav2Active()`，等待 AMCL 和 Behavior Tree (行为树) 动作服务器就绪。
2. **状态上报**：一旦 Nav2 状态转为 Active，`nav2_goal_bridge` 会向调度中心和 Web 面板周期性地发布 `/{ns}/nav_ready` 为 `True`。
3. **未就绪拦截**：如果 Nav2 未激活（即 `nav_ready` 为 `False`）：
   * 调度中心下发的目标点会被**拦截并缓存在内存中**（`_pending_goal`）。
   * `nav2_goal_bridge` **不会**调用任何底盘控制接口，小车保持**静止不动**。

## 3. Ground Truth 真值航点跟随模式（回退模式）

当系统算力不足（例如多车联调时 WSL2 卡顿）或不需要运行定位算法时，可通过启动 `warehouse_fleet.launch.py` 回退到真值跟随器模式。

### 3.1 核心组件
* **[ground_truth_waypoint_follower.py](file:///home/li/GazeboLib/src/amr_description/amr_description/ground_truth_waypoint_follower.py)**：不依赖地图和定位的轻量级闭环运动控制器。

### 3.2 控制机理与算法
* **位姿获取**：直接订阅 Gazebo 物理引擎输出的理想位姿（真值主题 `/{ns}/ground_truth`），绕过 AMCL 复杂的估计环节。
* **运动控制**：
  * **转角修正**：使用角度误差的比例控制（P控制器）引导小车朝向目标点。
  * **直线行驶**：当角度偏差小于阀值时进行直线驱动，基于距离大小进行平滑速度衰减。
* **避障安全**：虽然没有 Costmap 路径绕行能力，但该节点订阅了 `/{ns}/scan` 雷达数据，在检测到正前方存在障碍物（小于安全距离 `stop_dist`）时会强制刹车，障碍物移除后自动恢复。

## 4. 导航就绪状态（`nav_ready`）机制与现象说明

### 4.1 为什么导航未就绪时，小车还在移动？
这是初学者最常见的一个疑问。该现象只会发生在**真值回退模式**下：

1. **未就绪的判定标准**：调度中心与前端 Web 面板显示车辆的 `导航未就绪`（红标），其唯一的信号来源是 `/{ns}/nav_ready` 话题。该话题**仅**由 `nav2_goal_bridge` 节点进行发布。
2. **原因剖析**：
   * 在使用回退启动脚本 `warehouse_fleet.launch.py` 时，**Nav2 动作与 `nav2_goal_bridge` 节点根本没有被启动**。
   * 因此，调度中心收不到任何就绪主题发布，默认认为 `nav_ready = False`。
   * 然而，小车上挂载了轻量级闭环节点 `ground_truth_waypoint_follower`，它**不依赖就绪检测信号**，在接收到调度中心发出的 `goal_pose` 后，会立即自行运算并通过直接发布速度指令 `/cmd_vel` 让小车移动。

## 5. 两套驱动模式对比速查

| 特性 / 维度 | Nav2 导航驱动模式 | Ground Truth 真值回退模式 |
| :--- | :--- | :--- |
| **启动脚本** | `warehouse_fleet_nav2.launch.py` | `warehouse_fleet.launch.py` |
| **核心驱动节点** | `nav2_goal_bridge` + Nav2 Stack | `ground_truth_waypoint_follower` |
| **定位数据源** | AMCL 粒子滤波（基于 `/scan` + `/map`） | 仿真器理想坐标 `/ground_truth` |
| **路径搜索能力** | 具备 A*/Dijkstra 动态全局/局部避障绕行 | 仅支持两点间直线航迹跟随 |
| **遇到障碍物表现** | 重新规划路径绕过障碍 | 原地刹车等待障碍物离去 |
| **CPU/内存开销** | 较高（多车联调需要较大内存 and 错峰启动） | 极低（适用于轻量测试） |
| **Web 导航就绪灯** | 待 AMCL 激活收敛后转绿（`True`） | 持续红灯（`False`，因桥接器未启动） |
| **未就绪时小车状态**| 静止等待就绪并缓存目标点 | 直接利用真值定位正常行驶 |
